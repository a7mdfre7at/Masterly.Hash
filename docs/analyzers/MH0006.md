# MH0006: Obsolete Masterly.Hash 1.x API

| Property | Value |
|----------|-------|
| Category | Security |
| Default severity | Info |
| Code fix | Yes, when the call passes only the plaintext |

## Cause

A call to the 1.x `Masterly.Hash.Hash.ComputeHash`, to `IHash.ComputeHash`, or to `ComputeHash` on a subclass of
`Hash`.

## Why it matters

The 1.x API hashes with a single salted SHA-256/384/512 pass, which is fast to brute force (see [MH0001](MH0001.md)).
Masterly.Hash 2.0 keeps the 1.x types so that existing code compiles, but new hashes should come from `Password.Hash`.

## How to fix

```csharp
// Before
string stored = new Hash().ComputeHash(plainText);

// After
string stored = Password.Hash(plainText);
```

The code fix makes this change when the call passes only the plaintext, either positionally or as `plainText:`.
Calls that choose an algorithm or a salt are reported without a fix, because the replacement deliberately ignores
both.

Existing 1.x hashes keep working: `Password.Verify` accepts them, and `result.Rehash` holds an Argon2id replacement to
store after a successful login.
