# MH0001: Fast hash used on a password

| Property | Value |
|----------|-------|
| Category | Security |
| Default severity | Warning |
| Code fix | Yes, for `H(Encoding.X.GetBytes(password))` whose result is stored (returned or assigned), not compared |

## Cause

A general-purpose hash or MAC is applied to a value whose name says it is a password:

- `MD5`, `SHA1`, `SHA256`, `SHA384`, `SHA512`, `SHA3_*`: static `HashData` / `TryHashData` / `HashDataAsync`
- any `HashAlgorithm` (including `HashAlgorithm.Create(...)`): `ComputeHash` / `TryComputeHash` / `ComputeHashAsync`
- `HMAC*`: `new HMACSHA256(passwordBytes)` and static `HMACSHA256.HashData(key, passwordBytes)`

The rule inspects every input argument (not output buffers such as the `destination` of
`HashData(source, destination)` or `out` parameters), and follows `byte[] bytes = Encoding.UTF8.GetBytes(password);` when the
local is passed on. A symbol (local, parameter, field, property or method) matches when its name contains one of the
words **password, passwd, pwd, passphrase, pin**.

### Name matching

Names are split into words at camelCase humps, underscores and digits, and match on whole words, case-insensitively:
`userPassword`, `PASSWORD`, `pwd_2` and `PinCode` match; `spinner`, `pinned`, `opinion` and `compass` do not.

A match that is **followed by a qualifier word** (anywhere after it) describes metadata, not the password, and does
**not** count: `passwordPolicy`, `maxPasswordLength`, `passwordHint`, `passwordHash`, `passwordSaltBytes`,
`storedPasswordHashBase64`, `passwordResetToken`, `passwordExpiry`, and so on. A match **preceded by** `hashed`,
`encrypted`, `salted`, `masked` or `redacted` names a stored hash or ciphertext and does not count either:
`hashedPassword` (the ASP.NET Identity name for the stored hash), `encryptedPassword`. `nameof(password)` never
matches.

## Why it matters

MD5, SHA-1, SHA-2, SHA-3 and HMAC are built to be fast. A single GPU computes billions of SHA-256 hashes per second,
so a leaked table of salted SHA-256 password hashes falls to a dictionary attack in hours. Password storage needs a
deliberately slow, memory-hard function such as Argon2id.

## How to fix

```csharp
// Before
string stored = Convert.ToBase64String(SHA256.HashData(Encoding.UTF8.GetBytes(password)));

// After
string stored = Password.Hash(password);          // Argon2id, salted, PHC string
var result = Password.Verify(password, stored);   // constant-time, flags rehash
```

The code fix rewrites `Convert.ToBase64String(...)`, `Convert.ToHexString(...)`, `BitConverter.ToString(...)` or a
`var x = H(...)` declaration to `Password.Hash(x)`, adding `using Masterly.Hash;` when needed. It is offered only when
the result compiles (for example, not when the `var` local is later used as a `byte[]`) **and** the value is being
produced for storage: returned from a method or property, assigned to a field, property or local, or used to
initialize one, where every later use of that local is also storage.

`Password.Hash` uses a fresh random salt, so it is not a drop-in replacement on the verification side. The fix is
**not** offered when the value is compared (`stored == Convert.ToBase64String(H(...))`, `stored.Equals(...)`,
`string.Compare*`), passed to another call (a pre-hash fed to another hasher, a database query), returned from a
lambda or local function, or held in a local that is used that way: the rewrite would compile but never match again.
Replace such code with `Password.Verify(password, stored).IsMatch` by hand. It is also not offered for keyed hashes
(`HMACSHA256` and other `KeyedHashAlgorithm`s), because the rewrite would silently drop the key; move the key to a
pepper (`PasswordHasherOptions` with `HmacPepper`) instead.

If a method that returns the hash is also called on the verification side (`HashPassword(input) == user.Hash`),
change those callers to `Password.Verify` when you apply the fix. Existing stored hashes are
not converted: verify old hashes with the old code during migration, then store the output of `Password.Hash`.

## When to suppress

If the value is not actually a password, rename the symbol, or suppress with `#pragma warning disable MH0001` and a
comment explaining why.
