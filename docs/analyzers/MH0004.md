# MH0004: Password may be logged

| Property | Value |
|----------|-------|
| Category | Security |
| Default severity | Warning |
| Code fix | No |

## Cause

A password-named `string` or `char[]` value, or the result of `SensitiveString.Reveal()`, is passed to a log sink:

- `Microsoft.Extensions.Logging`: `LoggerExtensions.Log*` / `BeginScope`, `ILogger.Log` / `BeginScope`
- `System.Console.Write` / `WriteLine`
- `System.Diagnostics.Debug` and `Trace`: `Write*`, `Trace*`, `Print`, `Fail`

The rule follows the value through string concatenation, interpolated strings, `string.Format` / `Concat` / `Join`,
`params` arrays, `?:` / `??`, and string methods such as `Trim()`. Name matching is the same as in
[MH0001](MH0001.md): **password, passwd, pwd, passphrase, pin**, as whole words, ignoring names that end in a
metadata word (`passwordPolicy`, `passwordHash`). Non-text values such as `password.Length` or `bool isPasswordValid`
are ignored, and so is a `SensitiveString` itself, because it prints as `***`.

## Why it matters

Logs are copied to aggregators, indexed, backed up and retained for months, and far more people can read them than
can read the credential store. A password in a log is a leaked password.

## How to fix

Remove the password from the log statement. Log the user id or the outcome instead:

```csharp
// Before
logger.LogInformation("Login {User} {Password}", request.UserName, request.Password);

// After
logger.LogInformation("Login attempt for {User}", request.UserName);
```

Model request passwords as `SensitiveString` so that accidental logging prints `***`, and keep `Reveal()` calls next
to `Password.Verify`.
