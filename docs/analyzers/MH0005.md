# MH0005: Weak PBKDF2 parameters

| Property | Value |
|----------|-------|
| Category | Security |
| Default severity | Warning |
| Code fix | No |

## Cause

`new Rfc2898DeriveBytes(...)` or `Rfc2898DeriveBytes.Pbkdf2(...)` is called with:

- a **constant** iteration count below **100,000**;
- `HashAlgorithmName.MD5` or `HashAlgorithmName.SHA1` (or `new HashAlgorithmName("MD5" | "SHA1")`) as the PRF; or
- a constructor that omits the hash algorithm (defaults to **HMAC-SHA1**) or the iteration count
  (defaults to **1,000**), or both.

Iteration counts that are not compile-time constants (for example, values read from configuration) are not reported.

## Why it matters

PBKDF2's only defence against brute force is its iteration count. The
[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)
recommends 600,000 iterations for PBKDF2-HMAC-SHA256, 210,000 for PBKDF2-HMAC-SHA512 and 1,300,000 for
PBKDF2-HMAC-SHA1. The 1,000-iteration default is several hundred times too weak. The 100,000 threshold of this rule
is a floor that catches clearly broken code, not a recommendation.

## How to fix

```csharp
// Before
var kdf = new Rfc2898DeriveBytes(password, salt);

// After
byte[] key = Rfc2898DeriveBytes.Pbkdf2(password, salt, 600_000, HashAlgorithmName.SHA256, 32);
```

For password storage, prefer `Password.Hash`. It uses Argon2id, or PBKDF2-SHA512 with 210,000 iterations under the
FIPS-friendly `2026f` profile, and the hash string records which profile was used.
